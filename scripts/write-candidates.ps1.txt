Proposed fact/rule:
MineColonies has an internal event bus separate from NeoForge events. Access via:
  IMinecoloniesAPI.getInstance().getEventBus()

Subscribing to an event:
  IMinecoloniesAPI.getInstance().getEventBus()
      .subscribe(SomeModEvent.class, event -> { /* handler */ });

IModEvent: marker interface with getEventId() -> UUID.
All MineColonies internal events implement IModEvent.

DefaultEventBus: stores handlers in a Map<Class, List<EventHandler>>; dispatches by exact class match.
Exceptions in handlers are caught and logged as warnings -- they do not stop other handlers.

Key rules:
- Subscribe during mod init (e.g. FMLCommonSetupEvent), not on every tick.
- Handler lambda is EventBus.EventHandler<T> -- a @FunctionalInterface.
- IColonyEvent (raid/spawn events) uses a separate per-colony event manager, NOT this bus.
  Use this bus only for IModEvent implementations broadcast mod-wide.

Reason flagged: Gap for advisor system -- needed to hook into MineColonies-level events mod-wide.
Durability concern: Low -- direct source read from MineColonies API.
Recommended action: APPROVE
