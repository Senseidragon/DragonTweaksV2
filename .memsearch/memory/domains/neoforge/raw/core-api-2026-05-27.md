## Candidate 1

Domain: NeoForge
Change type: ADD
Title: DeferredRegister -- registration helper and factory methods
Source/evidence: docs/stubs/net/neoforged/neoforge/registries/DeferredRegister.java, NeoForge 21.1.230
Proposed fact/rule:
DeferredRegister<T> is the standard way to register objects in NeoForge 21.1.x.

Factory methods:
- DeferredRegister.create(Registry<T>, String namespace)
- DeferredRegister.create(ResourceKey<Registry<T>>, String namespace)
- DeferredRegister.create(ResourceLocation registryName, String modid)
- DeferredRegister.createBlocks(String modid) -- returns DeferredRegister.Blocks, store as that concrete type
- DeferredRegister.createItems(String modid) -- returns DeferredRegister.Items, store as that concrete type
- DeferredRegister.createDataComponents(ResourceKey<Registry<DataComponentType<?>>>, String modid)

Usage rules:
- Call register(IEventBus modBus) in the mod constructor or initializer to wire it to the mod event bus.
- Cannot call DeferredRegister.register(name, supplier) after RegisterEvent fires -- throws IllegalStateException.
- Cannot register a DeferredRegister to more than one event bus -- throws IllegalStateException.
- Supplier passed to register() must return a NEW instance every invocation (do not cache).
- DeferredRegister.Blocks overrides register() to return DeferredBlock<B>. Helpers: registerBlock(name, func, props), registerSimpleBlock(name, props), registerSimpleBlock(name).
- DeferredRegister.Items overrides register() to return DeferredItem<I>. Helpers: registerItem(name, func, props), registerSimpleItem(name, props), registerSimpleBlockItem(Holder<Block>, props).
- Store DeferredRegister.Blocks and DeferredRegister.Items using their concrete types, not as DeferredRegister<Block>.
Reason flagged: Core registration pattern used in every NeoForge mod.
Durability concern: Low. Factory API and constraints are stable across 21.1.x.
Recommended action: APPROVE

## Candidate 2

Domain: NeoForge
Change type: ADD
Title: DeferredHolder -- lazy registry reference
Source/evidence: docs/stubs/net/neoforged/neoforge/registries/DeferredHolder.java, NeoForge 21.1.230
Proposed fact/rule:
DeferredHolder<R, T> is a Holder<R> and Supplier<T> that lazily resolves the registry entry by ResourceKey.

Key behavior:
- Calling .get() or .value() before the registry is populated throws NullPointerException ("Trying to access unbound value").
- isBound() returns false until the registry contains the entry.
- asOptional() returns Optional.empty() if not bound.
- Specialized subtypes: DeferredBlock<B extends Block>, DeferredItem<I extends Item>.
- kind() always returns Holder.Kind.REFERENCE.
Reason flagged: Accessing DeferredHolder before registration completes is a common startup crash.
Durability concern: Low. Behavior is stable.
Recommended action: APPROVE

## Candidate 3

Domain: NeoForge
Change type: ADD
Title: AttachmentType -- data attachment registration and builder API
Source/evidence: docs/stubs/net/neoforged/neoforge/attachment/AttachmentType.java, NeoForge 21.1.230
Proposed fact/rule:
AttachmentType<T> represents data that can be attached to any IAttachmentHolder (Entity, BlockEntity, Level, ChunkAccess).
Must be registered to NeoForgeRegistries.Keys.ATTACHMENT_TYPES via DeferredRegister.

Builder factory methods:
- AttachmentType.builder(Supplier<T>) -- simple, no holder reference
- AttachmentType.builder(Function<IAttachmentHolder, T>) -- captures holder reference at construction time
- AttachmentType.serializable(Supplier<T>) -- shortcut for INBTSerializable types
- AttachmentType.serializable(Function<IAttachmentHolder, T>) -- with holder capture

Builder methods (chained before .build()):
- .serialize(IAttachmentSerializer) -- persist to disk
- .serialize(Codec<T>) -- serialize with codec (cannot capture holder reference)
- .serialize(Codec<T>, Predicate<T> shouldSerialize) -- conditional codec serialization
- .copyOnDeath() -- copy on player respawn or living entity conversion; REQUIRES serializer to be set first or throws ISE
- .copyHandler(IAttachmentCopyHandler<T>) -- custom copy logic; REQUIRES serializer set first
- .sync(StreamCodec) -- sync to all clients that track the holder
- .sync(BiPredicate<IAttachmentHolder, ServerPlayer>, StreamCodec) -- selective sync per player

Entity-specific rules:
- Serializable entity attachments are NOT copied on death by default.
- They ARE copied when the entity returns from the End (dimension transition).
- Opt into death-copy via .copyOnDeath() (requires serializer set first).

BlockEntity rule: call BlockEntity.setChanged() after modifying an attachment.
ChunkAccess rule: call ChunkAccess.setUnsaved(true) after modifying an attachment.
Reason flagged: Primary per-object data extension mechanism in NeoForge 21.x. Several non-obvious constraints.
Durability concern: Low. API is stable in 21.1.x.
Recommended action: APPROVE

## Candidate 4

Domain: NeoForge
Change type: ADD
Title: IAttachmentHolder -- interface for objects that hold data attachments
Source/evidence: docs/stubs/net/neoforged/neoforge/attachment/IAttachmentHolder.java, NeoForge 21.1.230
Proposed fact/rule:
IAttachmentHolder is implemented by Entity, BlockEntity, Level, and ChunkAccess.

Key methods:
- hasData(AttachmentType<?>) -- true if attachment exists
- getData(AttachmentType<T>) -- returns attachment; if absent, CREATES AND STORES the default value, then returns it
- getExistingData(AttachmentType<T>) -- returns Optional<T>; returns Optional.empty() if absent; does NOT create default
- getExistingDataOrNull(AttachmentType<T>) -- returns null if absent; backwards-compatible variant
- setData(AttachmentType<T>, T) -- sets value; returns previous value or null
- removeData(AttachmentType<T>) -- removes; returns previous value or null
- syncData(AttachmentType<?>) -- syncs to clients if AttachmentSyncHandler is configured on the type

Critical distinction: getData() has a side effect -- it creates and stores the default if the attachment is absent.
Use getExistingData() when you only want to check or read without triggering default creation.
Reason flagged: getData() side-effect is non-obvious and a common source of unintended state.
Durability concern: Low.
Recommended action: APPROVE

## Candidate 5

Domain: NeoForge
Change type: ADD
Title: BlockCapability -- querying and providing block capabilities
Source/evidence: docs/stubs/net/neoforged/neoforge/capabilities/BlockCapability.java, NeoForge 21.1.230
Proposed fact/rule:
BlockCapability<T, C> provides flexible access to objects of type T at a block position.

Query:
- level.getCapability(BlockCapability, BlockPos, context) -- returns T or null
- For repeated queries at the same position, use BlockCapabilityCache to cache the result.

Providing:
- Register via RegisterCapabilitiesEvent (mod bus event).
- For block entities: event.registerBlockEntity(capability, blockEntityType, (be, side) -> ...).
- For plain blocks: event.registerBlock(capability, provider, blocks...).

Invalidation rules:
- If a previously returned capability is no longer valid, or a new one is available, call level.invalidateCapabilities(pos) to notify caches.
- Plain blocks MUST call level.invalidateCapabilities(pos) in both onPlace() and onRemove().
- BlockEntities may call IBlockEntityExtension.invalidateCapabilities() as a convenience shortcut.
- Failure to invalidate causes stale BlockCapabilityCache results.

Factory methods:
- BlockCapability.create(name, typeClass, contextClass)
- BlockCapability.createVoid(name, typeClass) -- no-context capability
- BlockCapability.createSided(name, typeClass) -- @Nullable Direction context (most common pattern)

Proxyability: not proxyable by default. Capability definer marks proxyable via RegisterCapabilitiesEvent.setProxyable() at HIGH/HIGHEST priority. Mods forwarding "all" capabilities must skip non-proxyable caps.
Reason flagged: Capability invalidation is the most commonly missed requirement. Stale cache bug is silent.
Durability concern: Low.
Recommended action: APPROVE

Change type: ADD
Title: EntityCapability and ItemCapability -- factory and query API
Source/evidence: docs/stubs/net/neoforged/neoforge/capabilities/EntityCapability.java, NeoForge 21.1.230
Proposed fact/rule:
EntityCapability<T, C> provides access to objects of type T from entities.

Query: entity.getCapability(EntityCapability) -- returns T or null.

Factory methods:
- EntityCapability.createVoid(name, typeClass) -- no context
- EntityCapability.createSided(name, typeClass) -- @Nullable Direction context

Register via RegisterCapabilitiesEvent.registerEntity(capability, entityType, (entity, context) -> ...).

ItemCapability<T, C>: accessed from ItemStacks.
Register via RegisterCapabilitiesEvent.registerItem(capability, provider, items...).

Unlike BlockCapability, entity and item capabilities do not require explicit invalidation calls.
Reason flagged: Needed for mods exposing entity/item-based capability implementations.
Durability concern: Low.
Recommended action: APPROVE

## Candidate 8

Domain: NeoForge
Change type: ADD
Title: RegisterCapabilitiesEvent -- event bus and registration methods
Source/evidence: docs/stubs/net/neoforged/neoforge/capabilities/RegisterCapabilitiesEvent.java, NeoForge 21.1.230
Proposed fact/rule:
RegisterCapabilitiesEvent fires on the MOD event bus (implements IModBusEvent).

Registration methods:
- registerBlock(capability, provider, blocks...) -- throws IAE if blocks array is empty
- registerBlockEntity(capability, blockEntityType, (be, context) -> ...) -- includes runtime check that BE type matches
- registerEntity(capability, entityType, (entity, context) -> ...)
- registerItem(capability, provider, items...) -- throws IAE if items array is empty
- setProxyable(capability) / setNonProxyable(capability) -- call at HIGHEST or HIGH priority, by capability definer only

Important: registerBlockEntity() adds a type guard; if the block entity at the position has been replaced, the provider returns null.
Reason flagged: Wrong event bus (game vs mod) causes silent failure -- no provider is registered.
Durability concern: Low.
Recommended action: APPROVE

## Candidate 9

Domain: NeoForge
Change type: ADD
Title: EntityJoinLevelEvent -- entity added to level
Source/evidence: docs/stubs/net/neoforged/neoforge/event/entity/EntityJoinLevelEvent.java, NeoForge 21.1.230
Proposed fact/rule:
EntityJoinLevelEvent fires when an entity is added to a level (addFreshEntity or PersistentEntitySectionManager#addNewEntity).

Event bus: NeoForge GAME bus (not mod bus).
Sides: both logical sides.
Cancellable: yes -- cancelling prevents the entity from being added to the level.

Methods:
- getLevel() -- the level being joined
- loadedFromDisk() -- true if loaded from disk; always false on logical client

WARNING: This event may fire before the underlying LevelChunk reaches ChunkStatus.FULL.
Performing world interactions synchronously in this handler can cause chunk loading deadlocks.
Delay any world-accessing logic if needed.
Reason flagged: The chunk status warning is critical for avoiding deadlocks. Commonly missed.
Durability concern: Low.
Recommended action: APPROVE

## Candidate 11

Domain: NeoForge
Change type: ADD
Title: BlockEvent -- block lifecycle event subclasses
Source/evidence: docs/stubs/net/neoforged/neoforge/event/level/BlockEvent.java, NeoForge 21.1.230
Proposed fact/rule:
BlockEvent is abstract, fired on the NeoForge GAME event bus. All subclasses provide getLevel(), getPos(), getState().

Key subclasses:
- BlockEvent.BreakEvent -- server-side; cancellable; player attempts to break a block. May arrive pre-cancelled if Player#blockActionRestricted or block is GameMasterBlock; un-cancelling does not override those restrictions.
- BlockEvent.EntityPlaceEvent -- cancellable; block placed by entity; provides getPlacedBlock(), getPlacedAgainst(), getEntity().
- BlockEvent.EntityMultiPlaceEvent -- multi-block placement (e.g. beds); provides getReplacedBlockSnapshots().
- BlockEvent.NeighborNotifyEvent -- server-only; physics/redstone update (BUD switch); cancellable; provides getNotifiedSides().
- BlockEvent.FluidPlaceBlockEvent -- liquid creates a block (cobblestone gen, obsidian); cancellable; use setNewState(BlockState) to change result.
- BlockEvent.FarmlandTrampleEvent -- cancellable; entity tramples farmland.
- BlockEvent.PortalSpawnEvent -- cancellable; nether portal spawn attempt.
- BlockEvent.BlockToolModificationEvent -- cancellable; tool changes block state (axe strip, shovel flatten, hoe till). Check isSimulated() before modifying the world.
Reason flagged: Primary hooks for block behavior interception.
Durability concern: Low.
Recommended action: APPROVE

## Candidate 14

Domain: NeoForge
Change type: ADD
Title: IBlockEntityExtension -- NeoForge extensions on all BlockEntities
Source/evidence: docs/stubs/net/neoforged/neoforge/common/extensions/IBlockEntityExtension.java, NeoForge 21.1.230
Proposed fact/rule:
IBlockEntityExtension is automatically implemented by all BlockEntity instances in NeoForge 21.x.

Key methods:
- onDataPacket(Connection, ClientboundBlockEntityDataPacket, HolderLookup.Provider) -- handles incoming sync packet; default calls loadWithComponents if tag is not empty
- handleUpdateTag(CompoundTag, HolderLookup.Provider) -- client receives chunk update tag; default calls loadWithComponents
- getPersistentData() -- CompoundTag that persists to disk; for arbitrary custom data not covered by DataComponents
- onLoad() -- called when first added to world, or before first tick after chunk load/generation. Override this instead of a firstTick boolean in tick().
- requestModelDataUpdate() -- call when getModelData() output changes (client-only, no-op on server)
- getModelData() -- return ModelData for custom BakedModel rendering; default is ModelData.EMPTY
- invalidateCapabilities() -- calls level.invalidateCapabilities(be.getBlockPos()); safe when level is null (no-op)
- hasCustomOutlineRendering(Player) -- return true to enable custom outline rendering pass
Reason flagged: onLoad() pattern and invalidateCapabilities() are widely needed. getPersistentData() is the escape hatch for non-component persistent data.
Durability concern: Low.
Recommended action: APPROVE

## Candidate 15

Domain: NeoForge
Change type: ADD
Title: IItemExtension -- selected NeoForge extensions on all Items
Source/evidence: docs/stubs/net/neoforged/neoforge/common/extensions/IItemExtension.java, NeoForge 21.1.230
Proposed fact/rule:
IItemExtension is automatically implemented by all Item instances in NeoForge 21.x.

Key overrideable methods (@ApiStatus.OverrideOnly methods must be called via IItemStackExtension on ItemStack, not directly):
- onItemUseFirst(ItemStack, UseOnContext) -- fires before block activation; return InteractionResult.PASS to allow vanilla
- getBurnTime(ItemStack, RecipeType) -- furnace fuel value; 0 = not fuel, -1 = use vanilla. Takes precedence over NeoForgeDataMaps.FURNACE_FUELS. Prefer the data map unless burn time depends on NBT/components.
- canPerformAction(ItemStack, ItemAbility) -- true if stack can perform the given ItemAbility (axe strip, shovel flatten, etc.)
- getEquipmentSlot(ItemStack) -- return non-null to override equipment slot; null defers to vanilla logic
- canElytraFly(ItemStack, LivingEntity) -- true to allow elytra flight with this item in chest slot
- elytraFlightTick(ItemStack, LivingEntity, int flightTicks) -- return true to continue; use to consume durability/energy
- getDamage/setDamage/getMaxDamage -- stack-sensitive damage; internally use DataComponents.DAMAGE and MAX_DAMAGE
- supportsEnchantment(ItemStack, Holder<Enchantment>) -- whether enchantment can be applied via anvil or similar
- isPrimaryItemFor(ItemStack, Holder<Enchantment>) -- whether enchantment table can pick this; subset of supportsEnchantment
- canDisableShield -- default: only AxeItem disables shields
- getFoodProperties(ItemStack, @Nullable LivingEntity) -- stack-sensitive food properties; reads DataComponents.FOOD by default

Deprecated: onEntitySwing(ItemStack, LivingEntity) is @Deprecated(forRemoval=true, since="21.1"); use onEntitySwing(ItemStack, LivingEntity, InteractionHand) instead.
Reason flagged: getBurnTime precedence over data map, @OverrideOnly call pattern, and deprecated swing method are non-obvious.
Durability concern: Low.
Recommended action: APPROVE
